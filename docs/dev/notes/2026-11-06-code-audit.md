**Date:** 2026-11-06
**Read at:** `4553590`, `main` after #192
**Status:** report and tickets only. Nothing in it is built. ## How it was read

- Nine read-only passes in two rounds, each over one part of the package, with no file shared between the passes of a round. The first six: the capture path; the rules, their file and the editor; what happens after a match (escalation, audio, the panel, the Shortcut runner, snooze and the power hold); health, the self-test, on-call mode and the menu; the app target's wiring, the Setup Guide, Settings and the Inspector; and build, CI, the scripts, packaging and the tests as code. Then three more over what the first six had only skimmed: the notification's text from capture to what is seen and heard; the editor's ladder and alert editing and the guide's words; and the audio internals with the live-check harness in full. A last, mechanical sweep looked for the three kinds of defect the passes kept finding (a clock set back, a blank-text test that differs from `isBlank`, two tests of "this rule is in effect") and found none that is not below. That empty sweep is where the reading stopped.
- Each defect was confirmed by a second reading of the code it cites and, where it could be, by running it: a scratch program over copies of the pure sources (byte-identical to `4553590`, checked with `cmp`), a scratch program over `AVSpeechSynthesizer.write` that renders without playing, or `brew`'s own DSL source. None was confirmed against the running app.
- A mechanical pass beside them, for signal, not verdicts:
    - `swiftlint` with a configuration of its own outside the repository, as before (cyclomatic complexity 12 ignoring `case` statements, function body 60 lines, type body 400, file 600, force-try, force-cast, force-unwrap, nesting): 34 warnings over `Sources`. The 12 force-unwraps are each guarded on the line before or are `AVAudioFormat` constants; the 10 nesting warnings are the core's text enums. Four functions are over 60 lines: `AXBannerWatcher.swift:103` (78), `RuleSetCodec.swift:324` (69), `SetupCoordinator.swift:260` (63) and `BannerTracker.swift:190` (61).
    - A token-window search for repeated code: one repeat of 70 tokens (`SetupText.swift:188` and `:224`, `readsAgain` and `startsCaptureIfTrusted`, which the first audit records as deliberate) and six of 50.
    - Declarations whose name appears once anywhere in `Sources`, `Tests`, `Scripts` and `.github`: two, `applicationWillTerminate` and `userNotificationCenter`, both AppKit callbacks. Public symbols used only by tests: `RulesFile.Fingerprint.noFile`, which is the test's vocabulary for "no file".
- The baseline, Xcode 27.1 on macOS 27.2: `swift build --build-tests -Xswiftc -warnings-as-errors` clean, and `swift test --skip-build` 2600 tests with no failure (37 Shortcut, 20 storage, 2444 core, 4 capture, 21 panel, 74 audio; the `Executed N tests` lines).

## Verdict on the architecture

The architecture is still sound, and the debt is still small and local. What this read found is defects at the edges of the decisions, not in their shape.

- **The boundary holds.** `NotificationCore` imports Foundation (78 files) and CryptoKit (1) and nothing else; the libraries that touch the system depend on the core or on nothing; the app depends on all of them (`grep -rhoE '^import [A-Za-z]+' Sources/<target>`). `PurityTests` passes. There is no cycle and no third-party package.
- **The core decides, and the app carries out.** Of the defects below, all but three are in the core or a library and can be locked by a unit test. The other three are B15, whose start is the editor model's; B18, whose wake ask is the app delegate's; and B27, the cask.
- **What repeats now is a rule, not code.** Three kinds came up more than once. A clock set back is handled in `CaptureDeduplicator`, `HealthAlarmPlan.State.clamped`, `OnCallState`, `Snooze` and `EscalationCoordinator.Stamp`, and not in four other places (B17). A per-notification value is checked only where it is configured, so a template that is fine at load can still say nothing for one notification (B14). And "this rule is in effect" is asked in different words in different places (B16).
- **The source-text wiring tests are still the pin to check first.** They decided two rows here: B15's fix needs a new method name because a wiring test forbids the obvious one, and the Setup Guide's sentence about refused rules is asserted word for word, which makes its fix the owner's (B30).

## What this audit learned

- **A per-notification value needs the per-notification check.** The loader refuses a blank template and the editor's sample always has both fields, so nothing showed that one real banner can make a line with nothing in it. A check made where a value is configured says nothing of the value it produces.
- **A rule fixed once is a rule to look for everywhere.** The first audit clamped a clock set back in the deduplicator (B5); five types now clamp and four did not. When a defect's class is named, the fix is a search for its siblings, not one site.
- **Jitter is a bound's business.** The beep's repeat was given slack for the self-test's own run time; the bound it repeats after was not. A test that pins "599 s no, 600 s yes" pins the arithmetic, not the promise the page makes.
- **A converter that primes is not a converter that failed.** No output from one buffer is how a resampler starts. Only running every installed voice showed it, and only one voice of 184.
- **The pins decided a row again.** The Setup Guide's sentence looked like a one-line fix until `FirstRuleWayOnTests` was read: it asserts the sentence, word for word, for the very case that is wrong.
